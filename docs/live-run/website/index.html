High-Level Design Summary

The New SDLC With Vibe Coding

From ad-hoc prompting to agentic engineering — how AI is reshaping every phase of the software development life cycle, and what it demands from developers, teams, and organisations.

Source: Google — "The New SDLC With Vibe Coding" (Agents Whitepaper Series, May 2026) · Addy Osmani, Shubham Saboo, Sokratis Kartakis

Phase 01

From Syntax to Intent

Programming is undergoing its most significant transformation since high-level languages: developers now express what they want rather than how to build it, with AI agents handling implementation. By early 2026, 85% of professional developers regularly use AI coding agents and an estimated 41% of all new code is AI-generated.

Phase 02

The Vibe Coding to Agentic Engineering Spectrum

The decisive differentiator is not whether AI is used, but how much structure, verification, and human judgment surrounds its output. Vibe coding — casual prompting with minimal review — suits prototypes and personal projects; agentic engineering — automated test suites, CI/CD gates, and LM-judge evals — is required for production systems that organisations depend on.

Phase 03

Context Engineering

Output quality depends less on clever prompts than on richness of context: instructions, knowledge, memory, examples, tools, and guardrails. The boundary between static context (always loaded) and dynamic context (pulled on demand via Agent Skills) is a first-class architectural decision — too much static context wastes tokens, too little causes agents to forget critical rules.

Phase 04

AI Across Every SDLC Phase

Requirements become a live human-AI conversation producing specs and prototypes simultaneously. Architecture stays human-centric for trade-off decisions. Implementation shifts from writing to reviewing and guiding AI output. Testing demands both output evaluation and trajectory evaluation. Code review and deployment gain AI-powered augmentation, and maintenance of once-impenetrable legacy codebases becomes tractable.

Phase 05

Harness Engineering

A raw model is not an agent — it becomes one when a harness provides instructions and rule files, tools, sandboxes, orchestration logic, deterministic hooks, and observability. The harness, not the underlying model, dominates the behaviour developers experience: most agent failures trace back to a missing tool, a vague rule, or an absent guardrail rather than model capability.

Phase 06

Conductors and Orchestrators

Developers now move fluidly between two modes: conductor — real-time, hands-on direction of an AI pair-programmer inside the IDE — and orchestrator — async, high-level delegation to background agents that produce pull requests without a human writing a line of code. The orchestrator role demands specification, decomposition, evaluation, and system-design skills over syntax fluency.

Phase 07

The Economics of AI Development

Vibe coding appears cheap upfront but hides compounding operational costs: token burn from unstructured prompting loops, maintenance debt from inconsistent AI-generated code, and expensive security remediation. Agentic engineering requires upfront investment in context, tests, and harness infrastructure but dramatically lowers per-feature marginal cost — especially through intelligent model routing that reserves large frontier models for complex tasks and cheaper models for deterministic work.
